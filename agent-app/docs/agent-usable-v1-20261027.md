# Agent App 可用版实施与交接记录

执行范围：先完成正常使用流程，UI 图精细还原、预算控制、真实业务数据源按用户要求后置。原始总计划仍保留全部任务，不把本次可用版等同于全部长期目标完成。

## 入口与运行组成

本机独立试用入口为 `http://127.0.0.1:43301/login`；API 只监听 `127.0.0.1:43300`。Web 使用生产构建和同源 API/SSE 代理；API、租户专属 agent-worker、build-worker 共用独立数据库、签名密钥和制品目录。模型为真实 DeepSeek，未用确定性测试模型替代真实试用服务。

登录租户为“Agent 可用版试用”，用户名 `admin`。密码只保存在本机 `agent-app/.kf-trial-v1/access.json`，不得复制到补丁、日志或聊天中。初始化生成 `temporaryPassword`，首次登录必须修改；本次浏览器验收已执行改密，当前验收账户使用该私有文件的 `currentPassword`。用户再次自行改密后，文件中的旧值不会自动同步，应以用户的新密码为准。

新的试用库为 `kf_agent_trial_v1_20261027`，源码有 22 条迁移；新增 `202610270001_conversation_forks`。受保护的旧 18 迁移试用库、原 `.env` 的数据库目标、旧服务端口均未由本轮重置或替换。试用初始化不会运行 E2E seed。

## 使用路径

1. 登录后创建“新建工程”工作区，输入需求；讨论模式只沟通，规划模式停在方案，生成修改模式可继续构建。
2. 在真实蓝图确认卡核对内容，点击“确认蓝图并生成工程”。上传既有工程的路径还会出现原生变更审批，必须明确批准后构建。
3. 构建完成后从交付卡下载该轮工程包。扩展名为 `.gz`，包体沿用 KF 的 ZIP 格式，不应按标准 gzip 重新封装。
4. 在同一会话描述修改，重新核对蓝图/审批，产生新的工程修订。下载绑定实际 Run、BuildJob、revision、artifact 和 SHA，不按“最新文件”猜测。
5. 左侧支持新建/切换/搜索已加载会话、加载更多、改名、归档、恢复。活动或等待确认的任务不能直接归档；先完成或停止该轮。
6. 右侧“版本”可查看只读详情，下载精确历史包，从可靠消息锚点创建新会话。历史分叉保留上下文，不把工作区当前基线倒回旧版本，也不继承旧审批或活跃租约。
7. 图片路径先由租户管理员点击“授权租户图片外发”，再上传单张 PNG/JPEG/WebP，并勾选本轮外发同意。上传本身不代表外发同意。
8. 图片识别后逐项核对组件和未验证差异；可编辑区域、层级和文字，保存后重新确认。识别差异确认与随后蓝图确认是两个独立步骤。

草稿与模式按租户、用户、工作区、会话隔离，存放在当前标签页的 sessionStorage；登出清理当前所有者草稿。图片文件和外发同意不持久化；刷新后必须重新上传并同意，或明确选择仅发送文字，防止图片需求被静默降级。

## 本轮实现

| 范围 | 当前行为与主要边界 |
| --- | --- |
| 会话 API | v2 严格分页游标、消息稳定排序、改名、归档/恢复、活动时间和首条自然语言标题；跨租户/资源游标拒绝；v1 只读数组兼容保留 |
| 工作台 | 真正接入会话管理、分页、URL/浏览器前进后退、独立草稿、归档只读、明确图片授权；迟到响应不能覆盖其他会话或新草稿 |
| 历史交付 | 只读详情和历史下载绑定原构建；模块历史查找对应检查点，最多扫描 512 项，不以最新状态替代旧证据 |
| 历史分叉 | `ConversationForkRequest` 以租户/源会话/客户端请求保证幂等，检查消息→Run→版本；按最多 256 个实际执行祖先 Run 的逻辑顺序截取，排除排队/后续/旁支消息；最多 4096 条/8 MiB，清除旧 runId、receipt 和技术 JSON |
| 视觉启用 | 默认仍关闭；显式 runs/workbench/vision 与准确租户 allowlist 才开放，且保留管理员策略、逐次同意、能力和冻结身份检查 |
| 失败重试 | 在同租户/工作区/会话中追溯原始文字需求，最多 32 个祖先并拒绝循环；不复制已消费回执。creative-v2 重新生成蓝图并确认，legacy 保留原路由但仍要求新的原生审批 |
| 已生成工程续改 | 精确旧 GenerationSnapshot/成功 job/artifact/HMAC 与真实包检查为控件、页面、本地状态签发不外传的复用证据；保留 ID，不凭控件名或任意上传包授予覆盖权 |
| 原生名称及几何 | 新生成页、布局、控件名最长32字符；对照KF开发态规则；混合已有/新增控件时严格把批准绝对坐标转换为原生局部坐标，不放松geometry校验 |
| 重复项续改 | 结构投影v2提供完整有界mockData、原始key及布局/父子事实；既有记录key/类型/集合受保护，显示值和排序可改，防止A改B留下两条；最多一次补正 |
| 图片模型配置 | 识别、独立蓝图和语义工程使用冻结模型路由；显式开启时蓝图及工程均支持思考，补正最多一次；同一文本控件的观察要求按完整原文组织，数据快照优先 |
| 文字模型配置 | 语义工程生成读取显式思考策略与服务器超时；意图识别保留原有策略；默认配置不变，修复调用仍有界 |
| 可复现试用 | init/start/status/stop；数据库及文件所有权标记、独立随机凭据、UTC 校验、三服务监督、私有日志，同源代理；子服务异常则整组停止并返回非零 |

新增读写接口：`GET/POST /api/v2/conversations`、`GET/PATCH /api/v2/conversations/:id`、`GET /api/v2/conversations/:id/messages`、`GET /api/v2/workspaces/:workspaceId/revisions/:revisionId`、`POST /api/v2/conversations/:id/forks`。写请求继续受登录、租户与 Origin 防护。

## 验证范围与证据

完整验收结果、制品 SHA 和最终回归计数在 `agent-next-acceptance.md`；公开合成样本在 `outputs/usable-v1-20261027/`。目录中没有 API Key、会话 cookie、完整批准回执或隐藏思维链。私有原始调试资料不会进入补丁。

本轮发现并保留了真实负例：最初文字语义生成/修改出现无效 JSON；旧重试用泛化文本丢失原需求；试用启动未开启独立参考图上传；服务器本地时区使 raw SQL 与 ORM 时间不同；历史模块包被最新检查点挡住。这些问题的修复、重新验证和仍未通过的真实样本分别记录，不把模型随机失败抹成成功。

## 可用版边界及下一步

- 最终三份包均在授权KF环境独立导入、逐页读回相等，标准门户登录后开发态打开，无名称警告或脚本错误；本次测试席位已释放。尚未发布运行，因此不宣称运行态、交互或视觉验收通过。
- 模型输出仍可能不合法；失败不产生成功包，不无限付费重试。图片任务的自动“重试”保持关闭，需要新提交图片、重新同意、审核和独立确认。
- 已由图片生成的工程目前不接受普通文字续改；会明确要求重新上传图片、同意及审核，不能把旧 OCR 或回执作为本轮外发授权。跨版本图片内容复用与局部编辑的可信新同意协议属于 T23 后续工作。
- 旧长名生成基线只读和历史下载可用，继续生成在模型调用前明确拒绝并提示新建工程；不改写旧签名包。新短名基线继续修改已实测保留全部7处GUID及所有包路径。
- 已有repeater的记录key集合增删需后续可信删除协议，本版只改显示值/排序；新建独立repeater仍可用。模型必须保留已有布局类型及直接父子关系，不静默迁移类型。
- 当前图片入口为单张参考图。真实业务源、实时绑定、通用局部编辑、视觉替代控件、完整原生自动验收、成本 A/B 和预算拦截仍在原计划中。
- 会话搜索限已加载记录；消息结构化 parts 尚未面向客户端开放，历史先以清洗后的文字呈现。完整未读统计、时间线产品细节及跨平台部署矩阵继续按原任务台账推进。
- 对 UI 图的 1:1 还原、只读文字控件/字体、图表、画布比例等，回到 `2026-10-27-agent-native-visual-fidelity.md` 专项处理，不阻断本轮流程收口。

启动、迁移、停止和回退步骤见 `agent-next-release-runbook.md`。修改清单按本轮 SHA 基线生成，不以整个 dirty 工作树作为本轮补丁。
