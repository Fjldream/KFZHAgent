# 同会话排队、基线衔接与审批取消交接

日期：2026-10-21。功能标注统一为“Agent工作台迭代”。接续 `run-control-20261020.md`；预算限制按维护者要求继续暂缓。

“生成图”在代码中指 LangGraph 工作流（读取需求→规划→确认→编译→构建），不是 AI 画图片。本批没有接视觉模型或收费画图接口。

## 本批交付

### 1. 同会话持久队列

- 普通 message 可以在 QUEUED / RUNNING / BUILDING / CANCEL_REQUESTED 期间受理，保持原运行不变，新 run 绑定队尾 predecessorRunId；同一会话仍只有一个执行者。
- 在相同会话事务锁内创建用户消息、run、预算记录和 queued 事件。相同请求仍返回原 run；不同请求串成 FIFO，不再返回旧的 RUN_IN_PROGRESS。
- 每会话最多 20 条 QUEUED 普通输入，超出返回 409 RUN_QUEUE_FULL；重发已受理请求不受此限制，合法审批继续不因队列已满被锁死。
- WAITING_INPUT / WAITING_APPROVAL 仍是业务屏障，旧队列不能自行充当确认。用户新提交的澄清/合法继续排在屏障之后、已有队列之前，并重接直属排队后继。
- WAITING_APPROVAL 仍拒绝普通消息；确认/审批哈希不匹配时不消费等待轮次。已记录停止意图的审批只允许 cancel，不能趁间隙 approve。
- 保留前序实现的“原等待 run CANCELLED + supersededByRunId”接管语义，并非把审批未完成的运行标成成功。

### 2. 模型消息视图隔离

Run 内读取最近消息改按前序链组装，而非直接取全会话最新消息。排序以执行前序为准，每组内部再按时间/id 稳定排序；确认/澄清晚于队列入库时，当前队列输入仍位于本轮上下文末尾。

未来 queued 输入不进入正在执行的 run；未执行就取消的队列输入也不进入后续模型上下文。助手回复绑定真实 runId，禁止跨租户/跨会话使用执行作用域。仅早于链起点的无 runId 历史消息可作为旧历史补入。

上下文仍最多 20 条；前序链最多追溯 256 层，并有环检测。旧 SSE 没有 Run 执行作用域时继续使用原读取方式，不声称 T12 双入口兼容已经完成。

### 3. 基线只能有证据地前进

受理时保存 `inputSnapshot.baseRevisionPolicy`：普通、未固定基线的排队输入可 follow-predecessor；显式 expectedBaseRevisionId、确认/审批、retry 等固定基线。已有记录没有策略时按 fixed 处理，不批量猜测或改写历史。

领取时锁定 queued 行与工作区，在事务中决定：

1. workspace 基线未变：正常领取。
2. 基线变化：只有 follow-predecessor，且最近有效前序成功、区间内每一个修订都能绑定本会话前序链的成功 run，才更新基线并写一次 baseline.changed。
3. 其他会话的修订、缺失/循环/超深证据、固定基线或其他未知变化：写 FAILED / BASE_REVISION_CONFLICT 和终态事件，不执行模型/编译。

不能只检查“前序成功且看到同一个版本”：一次新的澄清/讨论不能把外部会话产生的修订算作本会话交付。已加红绿测试覆盖该错误及连续多个本会话修订的正确衔接。

生成工作流固定使用 Run 准入基线；即使执行中工作区前进，load-context 也不暗换。构建入队再次验证 input.baseRevisionId 与持久 Run 基线完全相同，保留原构建提交的 workspace stale-base 守卫。

### 4. 原生审批中断的停止与恢复

原生 pending checkpoint 必须被 Command(cancel) 实际消费，不能只改数据库状态：

- 已进入等待审批：沿用原生取消后继。
- 停止恰好先于 WAITING_APPROVAL 落库：保留真实等待屏障与 cancelRequestedAt；worker 下一轮安排确定性的原生取消后继。
- checkpoint 已提交，但停止抢在流投影前：读取已提交中断，保留审批屏障，不遗弃 checkpoint。
- worker 在该边界退出：恢复时仅以已中止的信号清点 checkpoint，不启动普通生成；随后同样安排取消后继。

内部取消使用 `cancel:<原runId>` 幂等键，与用户取消端点一致；可重入、不重复消费。旧审批基线过期时仍可取消，但不能在未经确认的新基线上批准。

恢复不重复写同一 approval.required。已消费的原 run 记录 supersededByRunId；公开事件只含受限摘要/哈希，不暴露模型隐藏思维链。

原有 PENDING / ADMITTED / QUARANTINED ConversationTurnFence 保护保持不变。没有自动删除硬崩溃屏障，也未声称完成 OS kill 故障演练。

### 5. 工作台

- 运行中发送显示“将排队”，受理成功才清草稿；正在停止/提交控制请求或等待审批时禁止竞争发送。
- 最新运行查询优先返回业务屏障/执行者，其次返回队列头，最后返回逻辑链尾，不再简单按创建时间选最新行。
- 新输入排队后仍显示当前实际执行的 run；当前事件结束后自动跟进后继。停止按钮不会因为排队而错误指向新输入。
- 遇到 BASE_REVISION_CONFLICT，显示“重新规划”而不是盲目重试；点击只切换到规划模式并提示核对版本，不直接发起模型调用。
- `run-plan@4` 使旧的整步 memo 哈希失效，防止复用旧队列/基线语义。
