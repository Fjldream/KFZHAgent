KF 通用模块生成架构

模型负责理解和组合，确定性引擎负责把方案可靠地落成 KF 原生工程。

Agent / 大模型决策 确定性平台能力 交付质量门禁 交付成果

1. 需求与效果蓝图

需求澄清 Agent理解业务目标、用户、数据、交互和视觉方向。
→
效果蓝图 Agent输出页面模块、内容样例、关键交互和验收标准。
→
客户确认确认最终效果目标，而不是直接确认底层控件 JSON。

2. 模块级实施规划

模块规划 Agent选择模块类型、顺序、内容、数据绑定及受控视觉变体。
→
ModulePlan结构化计划：Hero、KPI、卡片网格、趋势图、表格、表单等。
→
蓝图覆盖校验每个核心蓝图模块必须映射到真实 ModulePlan。
通用模块注册表门户模块、工业看板模块、管理页面模块；含布局变体和必需槽位。
KF 能力注册表记录可用原生控件、字段、样式、状态、交互及版本化适配信息。
资产目录与 Asset Tool内置资源、用户上传资源、包内路径；禁止模型编造文件名。

3. 确定性展开与 KF 工程生成

Module Compiler把模块展开为布局、控件树、约束、内容槽位和交互声明。
→
UIImplementationSpec只包含经过注册表验证的原生控件、资产引用和结构化样式。
→
KF Client Tools生成 ChangePlan、JSON、资源文件与可导入客户端工程。
核心原则：模块内部布局由模板保证；Agent 可以组合模块和选择变体，但不能绕过 KF 能力注册表直接写任意 CSS、资源路径或原生 JSON。

4. 双层质量门禁

强制阻断缺模块、缺资源、残留模板控件、越界、关键字段/交互缺失、未验证 KF 能力。
+
交付警告次要间距、阴影、非关键动画、可选装饰缺失；进入交付报告。
→
自动修复 Agent仅针对门禁报告修改 ModulePlan，再重新编译，不直接篡改工程 JSON。

5. 成果与持续修改

KF 客户端工程包原生可编辑、可导入、可继续在 KF 开发态修改。
交付报告蓝图覆盖、模块清单、能力缺口、警告和资产清单。
继续对话修改定位到模块和槽位做增量变更，未涉及模块保持不动。
