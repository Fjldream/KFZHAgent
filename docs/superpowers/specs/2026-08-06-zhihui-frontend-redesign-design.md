# 智绘（KF Solution Agent）前端改造设计

日期：2026-08-06
状态：用户已确认（2026-08-06）

## 1. 结论

将 `agent-app/apps/web`（Vue 3 + vue-router + 手写 CSS，零依赖）从「五面板同屏堆叠」的传统工作台，重构为 **状态驱动的自适应工作台**（方案 C，用户选定）。借鉴 Google Stitch 的任务流程（对话驱动一切、分阶段引导、对话+预览双栏），视觉基准采用苹果设计语言（apple-design skill）。产品名暂定 **智绘**。

**核心架构原则：**

> 对话是主心骨，永远连续；UI 不设固定 Tab，由工作流状态（SSE `stage`）驱动右侧情境面板自动切换内容；计划确认以全屏弹层浮现。

## 2. 范围

### 2.1 包含

- 登录页、强制改密页视觉重设计（苹果风）
- 新增**工程列表页** `/workspaces`（卡片式）
- 工作区 `/workspaces/:id` 整体重构：双栏布局 + 情境面板 + 全屏计划确认弹层
- 零依赖苹果风设计系统（设计令牌 + 动效规范）
- 前端 `stage` 推导逻辑（`idle | approval | building | ready | error`）
- 小改后端：新增 `GET /api/workspaces`（当前租户工作区列表）

### 2.2 不包含

- 不改 SSE 协议、不改 LangGraph 工作流状态机
- 不引入第三方 UI 库/样式框架（保持零依赖）
- 不新增组件库依赖、不改后端认证/审批逻辑
- 测试后补（本次重构完成后同步更新单元测试与 Playwright E2E）

## 3. 页面与路由结构

```
/login                    登录页（毛玻璃卡片、单一主按钮）
/change-password          强制改密页（同视觉体系）
/workspaces               工程列表页（卡片式：工程名、模式、最近修订、进入）
/workspaces/:id           工作区（状态驱动自适应工作台）
/                          → 重定向 /workspaces
```

路由名称与守卫不变；工程列表页为新增视图，现有 `WorkspaceView` 的"无工作区入口"逻辑迁移为独立列表视图。

## 4. 工作区布局（核心）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏（毛玻璃 backdrop-filter）：◈ 智绘 │ 工程名 · 状态胶囊 │ 用户 · 退出 │
├──────────────────────────────────────────────┬───────────────┤
│                                              │               │
│   对话流（主心骨，始终可见）                  │  情境面板      │
│   · 消息气泡（我=右对齐强调色 / 助手=浅色）   │  （随 stage    │
│   · 底部输入框（毛玻璃，Enter 发送）         │   自动切换）   │
│   · 流式打字机效果（逐 token）               │               │
│                                              │               │
├──────────────────────────────────────────────┴───────────────┤
│ 底部条：预览缩略条（有 previewArtifactId 时出现）            │
└──────────────────────────────────────────────────────────────┘
```

### 4.1 情境面板随 SSE `stage` 自动切换

| stage（来自 SSE done 帧） | 右侧情境面板 | 其他 UI |
|---|---|---|
| `idle`（对话中） | 工程概况：结构树 + 最近修订列表 | 状态胶囊「对话中」 |
| `approval`（计划待确认） | 计划摘要 + 操作列表 + 预览/脚本警告 | **全屏确认弹层**浮起 |
| 构建中（QUEUED/RUNNING/VALIDATING） | 构建进度（确定性步骤动画）+ 六层校验流 | 状态胶囊「构建中」，进度条 |
| 构建完成（SUCCEEDED/FAILED） | 校验报告 + 下载按钮（主操作） | 预览缩略条出现，可下载 |

### 4.2 上传源包交互（upload 模式）

- `mode === "upload"` 且当前修订为空时：右侧情境面板切换为**上传引导**（拖拽 + 点击选文件的漂亮交互，毛玻璃虚线框 + 进度反馈），对话流同时引导"上传 KF 源包"
- 上传成功后情境面板回到工程概况，开始正常对话迭代
- 「新建工程 / 上传工程」双入口保留在工程列表页（卡片新建 + 次级上传入口）

### 4.3 全屏计划确认弹层（本次最重要交互）

- 背景：对话流被模糊压暗（`backdrop-filter: blur + dim`，符合苹果"dim to focus"）
- 内容：计划摘要 → 精确操作列表（create/update/delete，破坏性红色标记）→ 脚本类变更单独区块 → planHash 只读展示
- 操作：**批准计划**（主按钮）/ **要求修改**（次要）/ **取消计划**（文字链接）
- 进入/退出动画：spring 语义（弹层进入轻弹性 `damping ~0.8`，普通过渡 `damping 1.0`），从触发它的对话消息处缩放展开（spatial consistency）
- 批准后弹层以弹簧收拢退出，情境面板切入构建状态
- 中断可逆：弹层动效可随时反向，不锁输入

## 5. 视觉设计系统（苹果风，零依赖手写 CSS）

- **字体**：`system-ui` 栈（SF 风格）；大标题负 tracking（`-0.02em`）、正文 0、小字正 tracking；行高随字号反向（大标题 1.05，正文 1.5）
- **色彩**（浅色为主）：
  - 背景 `#F5F5F7`（苹果灰）、卡片纯白
  - 主色 `#0A84FF`（iOS 蓝）、成功 `#34C759`（iOS 绿）、破坏性 `#FF3B30`（iOS 红）
  - 文字 `#1D1D1F`（主）/ `#86868B`（次）
- **材质**：顶栏/输入框/弹层 `backdrop-filter: blur(20px) saturate(180%)` 毛玻璃；滚动边缘渐变遮罩而非硬边框
- **圆角**：卡片 16px、按钮 10px、弹层 20px
- **反馈**：按钮 `:active { transform: scale(0.97) }`（pointer-down 即时反馈）
- **动效**：所有过渡用 spring 语义；弹层/面板用 Web Animations API 实现可中断动画；进入退出同路径；`prefers-reduced-motion` 降级为纯透明度渐变；`prefers-reduced-transparency` 下毛玻璃变实底
- **品牌**：顶栏「智绘」+ 简单几何 logo；登录页为居中毛玻璃卡片 + 品牌名

## 6. 数据流

- **不动后端协议**：SSE `streamMessageTurn` → `done` 帧 → store 路由到审批/构建（现状保留）
- **小改后端（仅 1 项）**：新增 `GET /api/workspaces` 返回当前租户工作区列表（供工程列表页）
- **前端 stage 推导**（放在 store composable）：由 `pendingApproval` / `buildJobStatus` / `lastDone.stage` 组合出 `idle | approval | building | ready | error`

## 7. 错误处理

- 对话错误：对话流内联红色提示（不弹窗）
- 构建失败：情境面板显示校验失败详情（复用现有 `ValidationReport` 内容），下载按钮隐藏
- 全屏弹层：加载计划详情失败时降级为仅有 summary + planHash（现状行为保留）
- 网络中断：输入框禁用 + 顶部状态胶囊变红「连接中断」

## 8. 测试策略

- 优先重构 UI，测试后补（用户已确认）
- 重构完成后：`WorkspaceView.test.ts` 同步新 DOM 结构、新增工程列表页测试、Playwright E2E 更新选择器，目标保持全绿（现有 243 tests + 3 个 E2E）

## 9. 待办边界（本次实现不做）

- 不处理多工作区并发编辑
- 不引入深色模式（本次浅色为主，设计令牌预留扩展）
- 不动后端审计/认证逻辑
